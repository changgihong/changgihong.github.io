## 문제

[프로그래머스 — 과제 진행하기](https://school.programmers.co.kr/learn/courses/30/lessons/176962)

## 접근 방법

새 과제의 시작 시각이 되면 현재 과제를 멈추고 새 과제를 시작한다. 여유 시간이 생기면 가장 최근에 멈춘 과제부터 재개하므로 스택으로 남은 작업 시간을 관리한다.

시각을 분 단위로 변환하고 시작 시각의 오름차순으로 정렬한다. 현재 과제를 스택에 넣은 뒤, 다음 과제 시작까지 남은 시간을 사용한다.

- 스택 맨 위 과제를 끝낼 수 있으면 완료 목록에 추가하고 남은 시간으로 다음 과제를 재개한다.
- 끝낼 수 없으면 남은 작업 시간만 줄인다. 다음 시작 시각에 새 과제를 스택 위에 넣는다.
- 마지막 과제 이후에는 새로 시작할 과제가 없으므로 스택 위에서부터 모두 완료한다.

남은 작업 시간과 다음 시작까지의 시간이 같다면 기존 과제를 먼저 완료 처리한다. 여유 시간이 0이 되면 멈춰둔 과제를 재개하지 않고 새 과제를 시작한다. 따라서 같은 시각의 완료와 시작도 문제의 우선순위를 따른다.

## 코드

```js
function solution(plans) {
  const tasks = plans
    .map(([name, start, duration]) => {
      const [hour, minute] = start.split(':').map(Number)
      return [name, hour * 60 + minute, Number(duration)]
    })
    .sort((a, b) => a[1] - b[1])
  const paused = []
  const answer = []

  for (let i = 0; i < tasks.length; i++) {
    const [name, start, duration] = tasks[i]
    paused.push([name, duration])
    if (i === tasks.length - 1) break

    let available = tasks[i + 1][1] - start
    while (available > 0 && paused.length > 0) {
      const current = paused[paused.length - 1]
      if (current[1] <= available) {
        available -= current[1]
        answer.push(paused.pop()[0])
      } else {
        current[1] -= available
        available = 0
      }
    }
  }

  while (paused.length > 0) answer.push(paused.pop()[0])
  return answer
}
```

## 복잡도와 경계 조건

과제 수가 `n`이면 정렬을 포함한 시간은 `O(n log n)`, 추가 공간은 `O(n)`이다. 각 과제는 한 번 등록되고 한 번 완료되며, 시간이 부족해 중단되는 처리는 다음 시작 시각마다 최대 한 번 발생한다.

여러 과제를 재개할 만큼 긴 공백, 연속된 중단, 완료와 다음 시작 시각이 같은 경우를 확인한다. 날짜가 바뀌어도 남은 작업 시간으로 처리하므로 별도의 시각 초기화는 필요하지 않다.
